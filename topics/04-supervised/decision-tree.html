Decision Tree

A Decision Tree predicts by asking a chain of simple yes/no questions, like a game of Twenty Questions. It is the most readable model in machine learning, and the building block of Random Forests and Gradient Boosting.

Beginner≈ 90 min5 interactive demos

1. The big idea

Twenty Questions. To guess an animal you don't ask random things. You ask the question that rules out the most possibilities: "Is it a mammal?" cuts the field roughly in half; "Does it have a striped coat?" would be a terrible first question. A decision tree learns, from data, which question to ask first, which second, and so on, until it is confident enough to answer.

The result is a flowchart. To predict for a new example you simply walk down the tree, answering each question about that example, until you arrive at an answer. Anyone can follow it, and you can print it and hand it to a doctor or a loan officer.

Part of the treeWhat it is
Root nodeThe first question, asked about every example.
Internal (decision) nodeA question about one feature ("Is Outlook = Sunny?", "Is age ≤ 30?").
BranchOne possible answer to a question.
Leaf nodeThe end of a path: the prediction (a class, or a number for regression).
DepthHow many questions deep the longest path is.

The whole learning problem is: which question should each node ask? The answer: the one that makes the groups after the split as pure as possible. To measure purity we need a number.

2. Measuring impurity: Gini and entropy

A group is pure if all its members have the same label (all "Yes"), and impure when the labels are mixed. Two standard scores, both 0 for a pure group and biggest for a 50/50 mix. If p is the fraction of "Yes":

ScoreIn wordsFormula (two classes)Range
Gini impurity (scikit-learn's default)1 minus the sum of squared class shares. Also the chance of mislabelling a random item if you label it at random using the group's proportions.1 − p² − (1−p)²0 to 0.5
EntropyHow "surprised" you are on average by a random item's label, in bits. Mixed groups are more surprising.−p·log₂(p) − (1−p)·log₂(1−p)0 to 1

The two curves have the same shape: peak at a 50/50 mix, zero when pure. In practice they choose almost identical trees, so don't agonise over which to use.

3. Information gain: choosing the best question

A question splits a group into smaller groups. A good question makes the smaller groups purer. We score a split like this:

Information gain = (impurity before the split) − (average impurity after the split).

"Average after" is weighted: a group with more members counts for more. So weighted impurity after = Σ (group size ÷ total) × (group impurity). The split with the biggest gain wins. (When you use entropy this quantity is called information gain; with Gini it is the Gini decrease.)

  • Rain (3 Yes, 2 No): Wind gives gain 0.971: Weak → all "Yes", Strong → all "No". Two pure leaves.

4. Numeric features: choosing a threshold

For a number such as hours studied, there is no fixed list of answers, so the tree asks a yes/no question of the form "is x ≤ t?". Which t? Try every midpoint between neighbouring values, score each with Gini, and keep the best.

Data: hours = 1, 2, 3, 4, 5, 6 with result = fail, fail, pass, fail, pass, pass (3 fail, 3 pass, so Gini before = 0.5).

5.5{1..5}: 2 pass / 3 fail → 0.48{6}: pass → 0(5/6)(0.48) + 0 = 0.4000.100

The best splits are t = 2.5 and t = 4.5 (tied at gain 0.25). The tree picks one and continues.

With several numeric features the tree tries every threshold of every feature at each node and takes the overall best. Because each question involves one feature at a time, the decision boundaries are always axis-aligned rectangles.

5. Overfitting: a tree that memorises

If you keep splitting until every leaf is pure, the tree can memorise the training data perfectly, even the noise and mislabelled examples: 100% training accuracy but poorer accuracy on new data. Such a tree is deep, with tiny leaves, and its rules ("if x ≤ 3.17 and y > 0.82…") are meaningless. It is the same overfitting story as before, and trees are especially prone to it.

A student who memorises. A student who memorises every past exam question and answer gets 100% on the practice papers but stumbles on a new question. A tree with unlimited depth memorises the training set in exactly the same way. Limiting the depth forces it to learn the general rules instead.

You can control the size of the tree (this is called regularisation or pruning):

HyperparameterWhat it limits
max_depthThe maximum number of questions in a row. The most important one.
min_samples_splitA node needs at least this many samples before it may split.
min_samples_leafEvery leaf must keep at least this many samples (bigger = smoother, less noise-chasing).
max_leaf_nodes, max_featuresCap the number of leaves; limit how many features are considered at each split.
ccp_alphaCost-complexity pruning: grow the full tree, then cut away branches that don't earn their keep.
class Aclass Bfilled = training · hollow = test · shading = the tree's prediction

At depth 1 the tree draws a single straight cut (underfit). As depth grows, the boundary becomes a staircase of rectangles that hugs the training points, and training accuracy climbs to 100% while test accuracy stalls or drops. Raising min_samples_leaf tames it.

6. Regression trees

To predict a number, the tree works the same way, with two changes: each leaf predicts the average of the training values that reached it, and a split is judged by how much it reduces the squared error (the sum of squared differences from the group's average) instead of Gini.

Data: x = 1..6 and y = 1.0, 1.2, 0.9, 3.1, 3.0, 2.9. Average y = 2.017; total squared error = 5.868.
Try t = 3.5: left {1.0, 1.2, 0.9} average 1.033, error 0.047; right {3.1, 3.0, 2.9} average 3.0, error 0.020. Total = 0.067, a huge drop. Compare t = 2.5: total 3.348; t = 4.5: total 3.255. So the best split is x ≤ 3.5, and the tree predicts 1.03 for x ≤ 3.5 and 3.0 above it.

Like KNN regression, a tree predicts a flat value inside each leaf, so the prediction is a staircase, and it can't extrapolate beyond the range of values it has seen.

7. Feature importance

Every time a feature is used in a split, it reduces impurity by some amount (weighted by how many samples were at that node). Add up these reductions per feature and normalise so they sum to 1: that is feature_importances_. In our cricket tree, Outlook (used at the root, where all 14 samples were affected) would score highest. Caveats: importances are computed on the training data, can favour features with many distinct values, and split credit among correlated features arbitrarily. For a fairer view use permutation_importance on test data.

8. Decision trees in scikit-learn

Trees need no scaling and no normalisation, which is a big convenience. Categorical text must still be encoded (see the pre-processing lesson), and scikit-learn's trees always make binary splits, so a category like Outlook becomes columns such as Outlook_Overcast (a yes/no question), and the tree it draws can look a little different from our three-way diagram.

import pandas as pd
from sklearn.tree import DecisionTreeClassifier, export_text, plot_tree

df = pd.DataFrame({
    "Outlook":  ["Sunny","Sunny","Overcast","Rain","Rain","Rain","Overcast","Sunny","Sunny","Rain","Sunny","Overcast","Overcast","Rain"],
    "Humidity": ["High","High","High","High","Normal","Normal","Normal","High","Normal","Normal","Normal","High","Normal","High"],
    "Wind":     ["Weak","Strong","Weak","Weak","Weak","Strong","Strong","Weak","Weak","Weak","Strong","Strong","Weak","Strong"],
    "Play":     ["No","No","Yes","Yes","Yes","No","Yes","No","Yes","Yes","Yes","Yes","Yes","No"],
})
X = pd.get_dummies(df[["Outlook", "Humidity", "Wind"]])      # one-hot encode the text columns
y = df["Play"]

tree = DecisionTreeClassifier(criterion="entropy", max_depth=3, random_state=0)   # or "gini"
tree.fit(X, y)

print(export_text(tree, feature_names=list(X.columns)))     # the tree as readable rules
print(dict(zip(X.columns, tree.feature_importances_.round(2))))
print(tree.predict(pd.get_dummies(pd.DataFrame({"Outlook": ["Sunny"], "Humidity": ["Normal"], "Wind": ["Weak"]}))
                   .reindex(columns=X.columns, fill_value=0)))   # -> ['Yes']
# plot_tree(tree, feature_names=X.columns, class_names=tree.classes_, filled=True)   # a picture (needs matplotlib)

Tuning the tree size with cross-validation (never with the training score!):

from sklearn.datasets import load_iris
from sklearn.model_selection import GridSearchCV, train_test_split
from sklearn.tree import DecisionTreeClassifier

X, y = load_iris(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=42, stratify=y)

grid = GridSearchCV(DecisionTreeClassifier(random_state=0),
                    {"max_depth": [1, 2, 3, 4, 5, None],
                     "min_samples_leaf": [1, 2, 5, 10],
                     "criterion": ["gini", "entropy"]},
                    cv=5)
grid.fit(X_train, y_train)
print(grid.best_params_, grid.score(X_test, y_test))

9. Strengths, limits and real-world use

StrengthsLimits
Easy to understand and explain; rules can be printedOverfits easily if left to grow
No feature scaling; works with numbers and categoriesUnstable: a small change in the data can give a very different tree
Captures non-linear patterns and feature interactionsAxis-aligned cuts approximate diagonal boundaries poorly
Fast prediction; gives feature importancesGreedy (each split is chosen without looking ahead); can't extrapolate

The instability is the big weakness, and it has a famous cure: build many different trees and average their votes. That is the Random Forest, and building trees one after another to fix each other's mistakes is Gradient Boosting / XGBoost. Both are coming up, and both are built from exactly the trees you just learned.

🏦 Loan approval

"Income > X and no missed payments → approve." Regulators like rules a human can read.

🏥 Medical triage

Emergency protocols are often literally decision trees: chest pain? → age? → ECG abnormal? → urgent.

📞 Support routing

Classify tickets and route them by product, urgency and customer tier.

🏭 Fault diagnosis

From sensor readings, find the branch that leads to "bearing wear", with rules engineers can check.

📱 Churn rules

Discover interpretable segments ("contract < 6 months and ≥ 3 complaints") and target them.

🎮 Game AI

Non-player characters decide what to do using tree-like logic (behaviour trees).

Key takeaways

  • A tree asks a sequence of yes/no questions; each leaf gives a prediction.
  • It chooses each question by information gain: (impurity before) − (weighted impurity after), using Gini or entropy.
  • It grows by repeating that choice on each new group (recursive partitioning), for numbers trying every threshold.
  • Left alone it overfits: control it with max_depth, min_samples_leaf or pruning, and choose values by cross-validation.
  • Regression trees predict the leaf average and split to reduce squared error.
  • Readable and scale-free, but unstable, so ensembles of trees (Random Forest, boosting) are the next step.
