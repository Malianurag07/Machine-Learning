Grid Search CV

Every model in this course has knobs: the k in KNN, the C and γ of an SVM, the depth of a tree, the learning rate of boosting. Grid Search CV is the standard way to choose them: try many combinations, score each one fairly with cross-validation, and keep the best.

1. The big idea: parameters vs hyperparameters

A model has two kinds of numbers. Parameters are learned from the data during training: the weights of a linear model, the split points of a tree. Hyperparameters are chosen by you before training and control how the learning happens: n_neighbors, max_depth, C, learning_rate, n_estimators, the regularisation strength α of Ridge and LASSO. The training algorithm cannot choose them for itself, because it would simply pick whatever memorises the training data best (a depth-unlimited tree, k = 1).

Tuning a radio. You turn two dials (frequency and fine-tune) and listen for the clearest sound. Trying every combination of dial positions systematically is a grid search. But you must judge "clear" fairly. If you tune while listening to the one song you will later be graded on, you will tune to that song's quirks. Cross-validation is the way of judging on songs the dials were not tuned on.

2. The fair judge: cross-validation

How do we score a setting honestly? Three tempting answers, and why each fails:

IdeaProblem
Score on the training dataRewards memorising. A depth-20 tree scores 100% and tells you nothing about new data.
Score on the test set, pick the bestThe test set has now been used to make a choice, so it no longer measures how the model does on genuinely unseen data. (This is called leakage.)
Hold out one validation setFine, but wasteful and noisy: the result depends on which rows happened to land in it.

K-fold cross-validation fixes the last one. Split the training rows into K equal folds. Then K times: train on K − 1 folds, validate on the remaining fold. Every row is used for validation exactly once, and the K scores are averaged.

Try "Rows: original order" with 2 folds. The data here is stored sorted by class (a common accident: think of a file sorted by date or by label), so one fold's training part contains a single class. That is why real code shuffles or uses stratified folds (each fold keeps the class proportions), which scikit-learn does automatically for classifiers when you pass cv=5.

3. Grid search: try every combination

Grid search is just this loop, run over a table of candidate values:

  1. List candidate values for each hyperparameter, e.g. C ∈ {0.1, 1, 10, 100} and γ ∈ {scale, 0.001, 0.01, 0.1}: the "grid" has 4 × 4 = 16 combinations.
  2. For every combination, run K-fold cross-validation and record the mean score.
  3. Pick the combination with the best mean score.
  4. Refit a final model on all the training data with those settings (scikit-learn does this automatically, refit=True).

Counting the work. Total model fits = (number of combinations) × K, plus one final refit. 16 combinations with 5 folds = 80 fits. It multiplies quickly: 4 hyperparameters with 5 candidate values each = 54 = 625 combinations, and × 5 folds = 3,125 fits. Grids blow up as you add hyperparameters ("the curse of the grid"), so use sensible, coarse grids first, then refine around the winner. Scale hyperparameters like C, γ, learning rate and α on a logarithmic grid (0.001, 0.01, 0.1, 1, 10...), because a change from 0.1 to 1 matters more than from 10.1 to 11.

  • Switch to random search: only 10 of the 48 cells are tried (dashed cells are skipped), with 50 fits instead of 240. Press "New random tries" a few times: it often lands on a setting nearly as good as the grid's best.
  • Look at the test accuracy reported for the winner, and compare it with the untuned deep tree. With only 60 noisy rows, tuning often gains little or nothing over the default (the repeated experiment below shows this on average).
  • "Repeat on 20 fresh datasets" shows the optimism trap: the best CV score, averaged over many datasets, is higher than the accuracy the chosen setting actually delivers on new points, because the "best of 48" was picked partly by luck. That is why you keep a test set untouched, or use nested cross-validation (section 5).
training accuracyvalidation accuracy (band = ± 1 standard deviation across folds)★ = best validation score

This is the picture behind every grid search, in one dimension: as the model gets more flexible, training accuracy keeps rising, while validation accuracy peaks and then falls. Grid search is finding the ★. With few rows the band is wide, so several depths are practically tied; prefer the simpler one.

4. Random search, halving and beyond

  • Random search (RandomizedSearchCV): instead of every grid point, sample n_iter random combinations from ranges or distributions. You choose the budget. It is often nearly as good as a full grid for a fraction of the cost, because usually only one or two hyperparameters really matter, and random sampling tries many different values of each of them, where a grid keeps repeating the same few.
  • Successive halving (HalvingGridSearchCV): start every candidate on a small slice of the data, throw away the worse half, give the survivors more data, and repeat. It spends the budget on promising settings. (Experimental in scikit-learn: it needs from sklearn.experimental import enable_halving_search_cv.)
  • Smarter searches such as Bayesian optimisation (tools like Optuna) use the results so far to decide what to try next. Worth knowing they exist; the ideas of this lesson (CV, refit, test set) stay the same.

5. Traps to avoid

  • Leakage through preprocessing. If you scale (or impute, or select features) before cross-validation, the validation folds have influenced the statistics used on the training folds. Put the preprocessing inside a Pipeline and pass the pipeline to GridSearchCV, so it is re-fitted on the training part of every fold. On the breast-cancer data below the leak happened to make no visible difference (both scored 0.9647), but with target encoding, feature selection or small datasets it can be large.
  • Optimistic best_score_. The winner's CV score is the best of many, as the demo showed. Report the score on a held-out test set that the search never saw, or use nested cross-validation (an outer CV that scores a whole grid search: cross_val_score(GridSearchCV(...), X, y)).
  • The wrong metric. The default score is accuracy for classifiers and R² for regressors. For imbalanced classes pass scoring="f1", "roc_auc" or "recall" (see the ML Workflow lesson on metrics).
  • Unshuffled or unstratified folds on sorted data (the first demo).
  • Chasing tiny differences. A CV score of 0.912 ± 0.03 and one of 0.915 ± 0.03 are a tie. Prefer the simpler model.
  • Time series. Never shuffle across time; use TimeSeriesSplit so you always validate on the future.

6. Grid Search CV in scikit-learn

Our hand example first:

import numpy as np
from sklearn.neighbors import KNeighborsClassifier
from sklearn.model_selection import KFold, cross_val_score, GridSearchCV

X = np.array([1.0, 1.7, 2.9, 3.4, 4.6, 5.2, 6.5, 7.1, 8.3, 9.0]).reshape(-1, 1)
y = np.array([0, 0, 0, 1, 0, 1, 1, 0, 1, 1])

for k in (1, 3, 5):
    s = cross_val_score(KNeighborsClassifier(n_neighbors=k), X, y, cv=KFold(5))
    print(k, s, s.mean())
# 1 [1.  0.5 0.5 0.5 0. ] 0.5
# 3 [1.  0.5 0.5 0.5 1. ] 0.7      <- identical to our hand-made table
# 5 [0.  0.5 1.  0.5 1. ] 0.6

grid = GridSearchCV(KNeighborsClassifier(), {"n_neighbors": [1, 3, 5]}, cv=KFold(5)).fit(X, y)
print(grid.best_params_, grid.best_score_)   # {'n_neighbors': 3} 0.7
print(grid.predict([[5.0]]))                 # [1]  (the refit model, trained on all 10 points)

(KFold(5) without shuffling is used here so that the folds match our pairs. In everyday code, cv=5 on a classifier uses stratified folds automatically.) Now a realistic example: an SVM in a pipeline, tuned on the breast-cancer data, with a test set that the search never touches. The comments are from an actual run with scikit-learn 1.9.0; other versions may differ slightly.

from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split, GridSearchCV
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.svm import SVC
import pandas as pd

X, y = load_breast_cancer(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, stratify=y, random_state=42)

pipe = Pipeline([("scale", StandardScaler()), ("svm", SVC())])
param_grid = {"svm__C": [0.1, 1, 10, 100],                 # step__parameter names
              "svm__gamma": ["scale", 0.001, 0.01, 0.1]}

search = GridSearchCV(pipe, param_grid, cv=5, n_jobs=-1, return_train_score=True)
search.fit(X_train, y_train)          # 16 combinations x 5 folds = 80 fits, then 1 refit

print(search.best_params_)            # {'svm__C': 10, 'svm__gamma': 0.001}
print(search.best_score_)             # 0.9765  (mean CV accuracy of the winner)
print(search.score(X_test, y_test))   # 0.979   (the refit model on the untouched test set)

results = pd.DataFrame(search.cv_results_)
cols = ["param_svm__C", "param_svm__gamma", "mean_test_score", "std_test_score", "mean_train_score"]
print(results.sort_values("rank_test_score")[cols].head(3))
#   C   gamma  mean_test  std_test  mean_train
#  10   0.001   0.9765    0.0166    0.9806
#   1   0.01    0.9718    0.0160    0.9789
# 100   0.001   0.9695    0.0095    0.9842
# (the worst combination, C=0.1 with gamma=0.001, scored only 0.709: badly under-fitted)

An honest observation from this run: the untuned SVC() in the same pipeline also scored 0.979 on the test set, so tuning did not improve the final number on this easy dataset. Its value here is safety: it protects you from a bad setting (a 0.709 combination sits in the same grid) and shows you the model is not fragile. On harder problems, or with boosting models, tuning usually matters more. Other search strategies, on the same data:

from scipy.stats import loguniform
from sklearn.model_selection import RandomizedSearchCV, cross_val_score, StratifiedKFold
from sklearn.experimental import enable_halving_search_cv        # needed once
from sklearn.model_selection import HalvingGridSearchCV

rand = RandomizedSearchCV(pipe, {"svm__C": loguniform(1e-2, 1e3),
                                 "svm__gamma": loguniform(1e-4, 1e0)},
                          n_iter=12, cv=5, n_jobs=-1, random_state=0).fit(X_train, y_train)
print(rand.best_score_, rand.score(X_test, y_test))   # 0.960  0.972   (12 x 5 = 60 fits)

halving = HalvingGridSearchCV(pipe, param_grid, cv=5, random_state=0).fit(X_train, y_train)
print(halving.best_params_, halving.score(X_test, y_test))   # C=1, gamma='scale'   0.979

# nested CV: an honest estimate of "tuning + fitting" as one procedure
outer = StratifiedKFold(5, shuffle=True, random_state=0)
print(cross_val_score(GridSearchCV(pipe, param_grid, cv=5), X, y, cv=outer).mean())   # 0.979

Random search found a slightly weaker setting than the full grid (0.960 CV) with 60 instead of 80 fits: on a grid this small it saves little, but on grids with thousands of combinations the saving is what makes tuning affordable. Different search methods can pick different winners that perform almost equally well, another sign not to over-trust tiny differences.

A practical recipe: (1) split off a test set and don't touch it; (2) build a pipeline with preprocessing and the model; (3) start with a coarse log-spaced grid or a random search; (4) look at cv_results_, especially the std and train-vs-validation gap; (5) refine around the best region; (6) evaluate once on the test set.

7. Strengths, limits and real-world use

StrengthsLimits
Simple, systematic and reproducible; works with any modelCost multiplies with every hyperparameter you add (the curse of the grid)
Cross-validation makes efficient use of small datasetsThe winner's CV score is optimistic; a separate test set or nested CV is needed
Embarrassingly parallel (n_jobs=-1)A grid can only pick from values you listed; the best value may lie between grid points
cv_results_ shows how sensitive the model is to each settingNot a substitute for good features and enough data

🏆 Competition pipelines

Every strong entry tunes its boosting and forest models with searches like these, judged by cross-validation on the training data.

🏥 Medical risk models

Stratified folds keep the rare outcome in every fold; scoring by recall or AUC instead of accuracy.

🤖 AutoML tools

Automated machine-learning systems are, at heart, large, smart searches over models and hyperparameters with cross-validation.

📈 Forecasting

Time-series splits validate each candidate on data that comes after its training window, mimicking real deployment.

🧪 Model comparison

Fair comparison of KNN vs SVM vs forest means tuning each one with the same CV procedure, then comparing on the same test set.

Key takeaways

  • Parameters are learned; hyperparameters are chosen by you. Choose them by validation performance, never by training score or the test set.
  • K-fold CV: split into K folds, train on K − 1, validate on 1, repeat K times, average. Shuffle or stratify the folds.
  • Grid search = CV for every combination in a grid, then refit the winner on all training data. Cost = combinations × K (+ 1 refit): 16 × 5 = 80 fits in our SVM example.
  • Use log-spaced grids for C, γ, learning rate, α; use random search or halving when the grid gets big.
  • Put preprocessing inside a Pipeline to avoid leakage; judge the final model once on an untouched test set (or nested CV), because best_score_ is optimistic.
  • Look at the standard deviation and the train-vs-validation gap: tiny differences are ties, and the simpler model wins ties.
