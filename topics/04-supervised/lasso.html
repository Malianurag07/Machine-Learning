LASSO Regression

LASSO is Ridge's stricter sibling. It also shrinks the coefficients, but it pushes the useless ones all the way to exactly zero, so it picks the important features for you.

Intermediate≈ 60 min4 interactive demos

1. From "make weights small" to "delete the useless ones"

Ridge (previous lesson) keeps every feature and just makes the weights smaller. That is great for stability, but sometimes you have 100 features and you suspect only 5 really matter. You would like the model to tell you which 5, and ignore the rest. That is exactly what LASSO does. The name stands for Least Absolute Shrinkage and Selection Operator: it shrinks weights and selects features at the same time.

Packing a suitcase with a weight limit. Ridge is like shrinking every item a little so everything fits. LASSO is like an airline's strict limit: you can't take everything, so you leave the least useful things at home completely, and pack only what earns its place. A weight of exactly 0 means "this feature stayed at home".

Why would you want that?

  • Simpler, easier to explain. "Price depends on area, location and age" beats "price depends on 87 things".
  • Less overfitting. Fewer features means fewer chances to memorise noise.
  • Cheaper. Fewer features to collect, store and compute in production.

2. The LASSO cost function

Same idea as Ridge (fit the data and keep weights in check), but the penalty uses the absolute value of each weight instead of its square. This is called the L1 penalty.

$$J(\theta)=\underbrace{\frac1{2n}\sum_{i=1}^{n}\big(h_\theta(x_i)-y_i\big)^2}_{\text{average squared mistake}}\;+\;\underbrace{\lambda\sum_{j=1}^{k}|\theta_j|}_{\text{L1 penalty}}$$

In words: LASSO cost = (average squared mistake) + λ × (the sum of the sizes of the weights, ignoring sign).

Ridge (L2)LASSO (L1)
Penaltyλ × sum of squared weightsλ × sum of absolute weights
Punishes…big weights a lot, tiny weights hardly at allevery weight by the same rate, however small
ResultSmall but non-zero weightsSome weights become exactly 0

λ is the strength (in scikit-learn it is alpha; this lesson's formula is exactly scikit-learn's Lasso objective, so λ = alpha). λ = 0 gives plain linear regression; a very large λ makes every weight 0, which leaves only the intercept (a flat line at the average).

Why does an absolute value create zeros while a square doesn't? Squaring a tiny number makes it tinier still (0.1² = 0.01), so the L2 penalty has almost no pull on small weights and never finishes the job. The absolute value pulls with the same force whether the weight is big or tiny (|0.1| = 0.1), so it can drag a small weight the whole way to zero and hold it there.

3. LASSO by hand: one feature

Take the data from the last two lessons: (1, 2), (2, 4), (3, 5), (4, 8), with n = 4 points. Recall Sxy = 9.5 ("how x and y move together") and Sxx = 5 ("how spread out x is"). Plain regression gives slope = 9.5 ÷ 5 = 1.9. For LASSO the rule is wonderfully simple:

slope = (Sxy − pull) ÷ Sxx, where pull = n × λ. If the pull is bigger than Sxy, nothing is left and the slope is exactly 0. Then intercept = average y − slope × average x (average x = 2.5, average y = 4.75).

Compare with Ridge on the same data: Ridge's slope went 1.9 → 1.58 → 0.95 → 0.38 as λ grew; it divides the slope by a bigger number, so it shrinks towards zero without ever reaching it. LASSO subtracts a fixed amount, so once the pull is bigger than the evidence, the slope hits zero and stays there. (Above λ = 2.375 the slope is 0 for good.)

4. The "dead zone": soft thresholding

The one-feature rule generalises. Suppose plain regression would give a feature the weight b. Here is what each method does to it:

  • Ridge: shrinks it proportionally: b ÷ (1 + λ) in its simplest form. A small b stays small but non-zero.
  • LASSO: moves it towards zero by λ: b − λ if b is positive, b + λ if negative, and if |b| is smaller than λ the result is 0. This is called soft thresholding.

See the flat stretch in the middle? Every coefficient inside the dead zone (from −λ to +λ) is set to exactly 0. Weak features fall inside it and vanish; strong features survive (a bit smaller). Raising λ widens the dead zone, so more features get eliminated.

5. Automatic feature selection

Here is a dataset with 8 features. Only x₁, x₂ and x₃ really affect y (true effects 3, −2 and 1.5); the other five are pure noise. The plot shows every coefficient as the strength λ increases (the LASSO path). As λ grows, features drop to zero one by one, weakest first.

Play with the slider. At a small λ LASSO keeps everything (like plain regression). At a moderate λ it should keep just the three real features and zero the noise; the "sweet spot" is what cross-validation finds for you. At a very large λ even the real features are removed (underfitting). Ridge with the same strength keeps all 8 alive (compare the last column).

6. The geometry: a diamond has corners

As with Ridge, we can view LASSO as "minimise the error, but stay inside a budget for the weights". With two weights, the Ridge budget was a circle. The LASSO budget |θ₁| + |θ₂| ≤ t is a diamond. The best answer is where the smallest error ellipse first touches the budget shape. A circle is smooth, so the touch point is usually somewhere along the curve. A diamond has sharp corners sitting exactly on the axes, and ellipses tend to hit a corner first. At a corner, one of the weights is exactly zero.

7. LASSO in scikit-learn

from sklearn.linear_model import Lasso

X = [[1], [2], [3], [4]]
y = [2, 4, 5, 8]

model = Lasso(alpha=1.0)      # alpha is lambda
model.fit(X, y)

print(model.coef_)            # [1.1]   plain regression gave 1.9
print(model.intercept_)       # 2.0
print(model.predict([[5]]))   # [7.5]

print(Lasso(alpha=3).fit(X, y).coef_)   # [0.]  the weight is exactly zero

These match the λ = 1 and λ = 3 rows of our hand calculation. Now a realistic workflow: scale the features (the penalty must treat every feature fairly), let cross-validation choose alpha, then look at which coefficients survived:

import numpy as np
from sklearn.datasets import make_regression
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LassoCV

# 100 features but only 5 really matter
X, y = make_regression(n_samples=300, n_features=100, n_informative=5, noise=10, random_state=0)
X_train, X_test, y_train, y_test = train_test_split(X, y, random_state=0)

model = make_pipeline(StandardScaler(), LassoCV(cv=5, random_state=0))
model.fit(X_train, y_train)

lasso = model.named_steps["lassocv"]
print("best alpha:", lasso.alpha_)
print("features kept:", np.sum(lasso.coef_ != 0), "of", len(lasso.coef_))
print("test R2:", model.score(X_test, y_test))
selected = np.flatnonzero(lasso.coef_)      # column numbers of the surviving features

You should see that LASSO keeps only a small number of the 100 features (close to the 5 real ones, plus perhaps a few weak extras). The exact count depends on the random data.

ParameterWhat it does
alphaStrength λ. 0 = plain regression; bigger = more zeros. Default 1.0 (usually needs tuning, and is often much smaller).
max_iterLASSO is solved step by step (coordinate descent). If you see a ConvergenceWarning, raise this or scale your features.

8. Ridge, LASSO or Elastic Net?

Ridge (L2)LASSO (L1)Elastic Net (L1 + L2)
Zeros out coefficientsNoYesYes
Feature selectionNoYesYes
Many small useful effectsGreatTends to drop someGood
Groups of correlated featuresShares credit evenlyPicks one, drops the rest (and the pick can change between samples)Keeps groups together
More features than samplesWorksKeeps at most n featuresWorks
scikit-learnRidgeLassoElasticNet(alpha, l1_ratio)

Rule of thumb. Suspect that only a few features matter and you want a simple, explainable model → LASSO. Believe that many features each contribute a little, or features are highly correlated → Ridge. Not sure, or correlated groups plus a wish for sparsity → Elastic Net (the l1_ratio parameter is the mix: 1 = pure LASSO, 0 = pure Ridge). Try all three and compare with cross-validation.

Always scale first. The penalty is applied to the weights, and a weight's size depends on the units of its feature. Without scaling, features measured in large units get an unfair advantage. Also remember that LASSO's "selection" is a statement about this dataset: with correlated features, which one survives can be somewhat arbitrary, so don't over-interpret a zero as "this feature is unimportant in the real world".

9. LASSO in the real world

🧬 Genetics

Tens of thousands of gene measurements, a few hundred patients. LASSO shortlists the handful of genes linked to a disease.

🏦 Credit scoring

Dozens of possible applicant attributes; regulators want a short, explainable model. LASSO keeps only the ones that matter.

📝 Text models

Bag-of-words features can number in the hundreds of thousands. L1-regularised models keep a small vocabulary of the most predictive words.

🏭 Sensor selection

Which of 300 factory sensors actually predict machine failure? Removing the rest saves money and simplifies the model.

📣 Marketing channels

Out of 25 possible ad channels, LASSO points to the few that genuinely drive sales, so budget can move from the rest.

🩺 Clinical risk scores

Doctors need a score based on a small number of measurements they can collect quickly. LASSO builds it.

Key takeaways

  • LASSO = linear regression + L1 penalty (λ × sum of |weights|).
  • Unlike Ridge, it sets some weights exactly to zero, so it does feature selection automatically.
  • One-feature rule: slope = (Sxy − n·λ) ÷ Sxx, and it becomes 0 when n·λ is bigger than Sxy.
  • Geometry: the L1 "diamond" has corners on the axes, which is where zeros come from.
  • Scale first, choose λ (alpha) with cross-validation (LassoCV); use Elastic Net when features are correlated in groups.
