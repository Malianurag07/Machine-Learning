Logistic Regression

Despite its name, Logistic Regression is a classification algorithm. It predicts the probability that something belongs to a class (spam, fraud, will-pass) and then turns that probability into a yes/no answer.

1. Why not just use linear regression for yes/no?

Suppose we want to predict whether a student passes (1) or fails (0) from the hours they studied. Linear regression draws a straight line through the 0s and 1s and reads the height as the prediction. Two things go wrong:

  • The line keeps going: it predicts −0.2 or 1.3, which cannot be a probability.
  • One unusual student (someone who studied 14 hours and passed) tilts the whole line, and the boundary between "pass" and "fail" moves for everybody.

What we want is an S-shaped curve that stays between 0 and 1 and is not thrown off by extreme points. That curve is the sigmoid, and a model built on it is Logistic Regression.

failed (0)passed (1)

A confidence dial. Imagine a doctor who weighs the evidence and turns a dial from 0 ("definitely healthy") to 1 ("definitely ill"). The more evidence for illness, the further the dial turns, but it can never go past either end. Logistic regression is that dial: it adds up the evidence like linear regression does, then squeezes the total into the 0-to-1 range.

2. The idea: a score, squeezed into a probability

Logistic regression works in two steps.

  1. Compute a score exactly like linear regression: z = θ₀ + θ₁·x (with more features: z = θ₀ + θ₁x₁ + θ₂x₂ + …). The score can be any number, from very negative to very positive.
  2. Squeeze it with the sigmoid function to get a probability between 0 and 1.
$$p=\sigma(z)=\frac{1}{1+e^{-z}}$$

In words: a huge positive score gives a probability near 1, a huge negative score gives near 0, and a score of exactly 0 gives 0.5. Some values:

probability p0.0180.1190.2690.5000.7310.8810.982

Then we turn the probability into a class with a threshold, normally 0.5: if p ≥ 0.5 predict class 1, otherwise class 0. Since p = 0.5 exactly when z = 0, the decision boundary is where the score is zero: θ₀ + θ₁x = 0, i.e. x = −θ₀ ÷ θ₁.

  • θ₁ (the slope) controls how sharp the switch is. Large |θ₁| gives a steep S (confident, almost a step); small |θ₁| gives a gentle S. A negative θ₁ flips the curve.
  • θ₀ (the intercept) slides the curve left or right, moving the decision boundary.

3. Odds and log-odds: how to read the weights

Probability and odds are two ways of saying the same thing. If p = 0.8 the odds are 0.8 ÷ 0.2 = 4 ("4 to 1 in favour"). Here is the neat fact about logistic regression: the score z is the logarithm of the odds (the "log-odds" or "logit"). So the model is a straight line in log-odds, and each weight has a clean meaning:

Rule: when x goes up by 1, the odds get multiplied by eθ₁.

Example. Suppose θ₁ = 0.8 for "hours studied". Then e0.8 ≈ 2.23, so each extra hour multiplies the odds of passing by about 2.2. If the odds were 1 to 1 (p = 0.5), one more hour makes them 2.2 to 1 (p = 0.69). Two more hours: 2.2 × 2.2 = 5 to 1 (p = 0.83).

A positive weight increases the chance of class 1, a negative weight decreases it, and a weight near 0 means "this feature hardly matters". That readability is a big reason banks and hospitals still like this model.

4. How does it learn? The log-loss cost

As with linear regression, we need a number that says "how wrong is the model", and then we adjust θ to make that number smaller. Squared error is a poor choice here (with a sigmoid it produces a bumpy landscape with flat patches). Instead we use log-loss (also called cross-entropy), which has a simple meaning: how surprised is the model by the truth?

For one sample, with p = the model's probability of class 1:

  • if the truth is 1: cost = −log(p). (The bigger p is, the less surprised, the smaller the cost.)
  • if the truth is 0: cost = −log(1 − p). (Being confident it's 1 when it's really 0 is a big surprise.)

The total cost J is simply the average of these costs over all the training samples. It is 0 for a perfect, fully confident model and grows as the model gets more wrong.

Notice the curve shoots up as the model becomes confidently wrong. Log-loss punishes overconfidence, which encourages honest probabilities.

The update rule is one you already know

Here is the pleasant surprise. The gradient-descent update for logistic regression looks exactly like the one for linear regression, except the prediction is now the probability p:

  • error = p − y (the probability minus the true 0/1 label)
  • new θ₀ = old θ₀ − α × (average of the errors)
  • new θ₁ = old θ₁ − α × (average of error × x)

One step by hand. Study hours x = 1, 2, 3, 4, 5, 6 and outcomes y = 0, 0, 1, 0, 1, 1. Start with θ₀ = 0, θ₁ = 0, so every score is 0 and every probability is 0.5. Take α = 0.5.
errors p − y = 0.5, 0.5, −0.5, 0.5, −0.5, −0.5.
average error = (0.5+0.5−0.5+0.5−0.5−0.5) ÷ 6 = 0.
average of error × x = (0.5 + 1.0 − 1.5 + 2.0 − 2.5 − 3.0) ÷ 6 = −3.5 ÷ 6 = −0.583.
θ₀ = 0 − 0.5 × 0 = 0; θ₁ = 0 − 0.5 × (−0.583) = 0.292.
The weight on hours becomes positive: more hours, higher chance of passing. Repeat many times and the S-curve settles.

5. More than one feature: the boundary becomes a line

With two features (say hours studied and attendance) the score is z = θ₀ + θ₁x₁ + θ₂x₂, and the boundary z = 0 is a straight line across the plot. Points on one side are classified as class 1, points on the other side as class 0. With three features the boundary is a flat plane, and so on. That is why logistic regression is called a linear classifier: it can only separate classes with a straight boundary.

Choosing the threshold: it is a business decision

0.5 is only a default. Moving the threshold trades one kind of mistake for the other:

SituationCostlier mistakeSet the threshold…
Cancer screeningMissing a real case (false negative)Lower (say 0.2): catch more, accept more false alarms → higher recall
Spam filterHiding a real email (false positive)Higher (say 0.9): only flag when very sure → higher precision
Balanced costsBoth similarAround 0.5, or pick the value that maximises F1 on validation data

6. More than two classes

For 3 or more classes (say flower species) scikit-learn extends the idea with the softmax function: compute one score per class, then turn the scores into probabilities that add up to 1, giving bigger scores a bigger share.

Softmax in words: probability of a class = e^(its score) ÷ (sum of e^(score) over all classes).
Example. Scores 2.0, 1.0, 0.1 → e^score = 7.39, 2.72, 1.11 (sum 11.21) → probabilities 0.66, 0.24, 0.10. The class with the highest probability wins. The two-class case is just a special case of this.

7. Logistic regression in scikit-learn

from sklearn.linear_model import LogisticRegression

hours = [[1], [2], [3], [4], [5], [6]]     # features: 2-D
passed = [0, 0, 1, 0, 1, 1]                 # labels

model = LogisticRegression()                # C=1.0, L2 penalty by default
model.fit(hours, passed)

print(model.intercept_)                     # about [-2.68]   (theta_0)
print(model.coef_)                          # about [[0.767]] (theta_1)
print(model.predict_proba([[1], [3.5], [6]]))
#  -> class-1 probabilities of about 0.13, 0.50 and 0.87
print(model.predict([[2], [5]]))            # [0 1]   class labels (threshold 0.5)
print(model.score(hours, passed))           # accuracy on this data

The decision boundary is where the score is zero: 2.68 ÷ 0.767 = 3.5 hours. (With almost no regularisation, C=1e6, the same data gives θ₀ ≈ −4.25 and θ₁ ≈ 1.21, a steeper curve. Regularisation makes the model less extreme.) A realistic version with scaling and evaluation:

from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import classification_report

X, y = load_breast_cancer(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, test_size=0.2, stratify=y, random_state=42)

model = make_pipeline(StandardScaler(), LogisticRegression(max_iter=1000))
model.fit(X_train, y_train)

print(classification_report(y_test, model.predict(X_test)))

proba = model.predict_proba(X_test)[:, 1]        # probability of class 1 for each patient
custom = (proba >= 0.3).astype(int)              # your own threshold instead of 0.5

On this dataset a scaled logistic regression typically reaches an accuracy in the mid-to-high 90s (percent); the exact figure depends on the split and library version.

8. Strengths, limits and pitfalls

StrengthsLimits
Fast, simple, works with little dataOnly a straight boundary (add polynomial features or use SVM/trees for curves)
Outputs probabilities, not just labelsStruggles when classes overlap heavily or interactions matter
Weights are easy to explain (odds multipliers)Sensitive to features on different scales unless scaled
Good baseline and easy to regulariseCorrelated features make individual weights unstable (use L2/L1)
  • Perfectly separable data. If one straight line separates the classes perfectly, the weights want to grow forever (the model wants to be infinitely confident). Regularisation (C) keeps them finite.
  • Imbalanced classes. With 1% positives, "always predict 0" is 99% accurate and useless. Use class_weight, a lower threshold, and precision/recall instead of accuracy.
  • Probabilities are only as good as the model. If you need well-calibrated probabilities (e.g. for pricing risk), check with a calibration curve.

9. Logistic regression in the real world

🏦 Credit scoring

Will this borrower default? Banks have used logistic scorecards for decades because each weight can be explained to regulators and customers.

🏥 Medical diagnosis

Risk of diabetes or heart disease from age, blood pressure, BMI. Doctors can read the odds multiplier of each factor.

📧 Spam filtering

Probability that an email is spam from word counts, links and sender features; the threshold decides what goes to the junk folder.

📱 Customer churn

Which subscribers are likely to cancel next month? Rank them by probability and offer a retention deal to the top group.

🖱️ Ad click prediction

Probability that a user clicks an ad. Large ad platforms use logistic models on huge sparse feature sets.

🕵️ Fraud detection

Probability a transaction is fraudulent; a low threshold plus human review catches more fraud.

🗳️ Marketing response

Who will respond to this campaign? Send offers only to people above a probability cut-off.

🧱 The building block of neural nets

A single sigmoid neuron is a logistic regression, and the output layer of many neural network classifiers uses the same maths (softmax).

Key takeaways

  • Logistic regression is a classifier: score z = θ₀ + θ₁x + …, then p = σ(z) = 1 ÷ (1 + e−z), a probability between 0 and 1.
  • Predict class 1 when p ≥ threshold (default 0.5). The decision boundary is where z = 0, a straight line/plane.
  • Each weight multiplies the odds by eθ for every +1 in that feature.
  • It learns by minimising log-loss ("how surprised is the model by the truth"); the update rule mirrors linear regression, using error = p − y.
  • Use regularisation (C, smaller = stronger), scale your features, and tune the threshold to the cost of mistakes. Prefer precision/recall over accuracy on imbalanced data.
