Random Forest

One decision tree is easily fooled by the quirks of its training data. A random forest grows hundreds of different trees, each on a slightly different view of the data, and lets them vote. The crowd is far more reliable than any single member.

Intermediate≈ 90 min4 interactive demos

1. The big idea: many different trees, one vote

In the Decision Tree lesson you saw the weakness of a single tree: grown deep, it memorises the training data. Change a few training rows and you can get a completely different tree. Statisticians call this high variance: the model's answer swings wildly with the sample it was shown. But notice something useful: a deep tree is not biased; it is just unstable. And unstable-but-unbiased is the perfect ingredient for averaging.

Ask a jury, not one judge. Imagine you must guess how many sweets are in a huge jar. Any one person's guess is poor: some guess too high, some too low. But take the average of 200 people's guesses and it is often startlingly close, because the individual errors point in random directions and cancel out. A random forest is that crowd: every tree is a slightly-wrong, slightly-different opinion, and the vote (or average) cancels the individual mistakes. The trick is that the crowd only works if the people did not all copy each other, so the forest works hard to make every tree see the world a little differently.

A random forest is a recipe with exactly three ingredients:

#IngredientWhat it does
1Bootstrap the rowsEvery tree trains on its own random re-sample of the training rows (drawn with replacement), so no two trees see the same data.
2Random features at each splitAt every split a tree may only look at a random handful of the features, which forces different trees to use different questions.
3Vote / averageClassification: the majority vote (or average of probabilities). Regression: the average of the predictions.

Ingredients 1 and 2 together are called bagging plus feature randomness ("bagging" is short for bootstrap aggregating). Each ingredient is explained next, with numbers.

2. Ingredient 1: the bootstrap (sampling with replacement)

Take a training set of n rows. A bootstrap sample is made by picking a row at random, writing it down, putting it back, and repeating n times. Because rows go back into the bag, the same row can be picked several times and others never get picked.

By hand: 8 rows

Rows are numbered 1 to 8. One possible bootstrap sample (8 draws): 1, 2, 4, 4, 6, 7, 7, 8.

Row 4 was picked twice, row 7 twice, rows 1, 2, 6 and 8 once each. Rows 3 and 5 were never picked. So this tree trains on 8 draws containing 6 distinct rows (75%), and rows 3 and 5 are its out-of-bag (OOB) rows: data this tree has never seen.

How many distinct rows should we expect? Each single draw misses a particular row with probability (1 − 1/n). All n draws miss it with probability (1 − 1/n)n. So a given row is in the sample with probability 1 − (1 − 1/n)n:

Rule of thumb: each tree sees about two-thirds of the distinct rows, and about one-third of the rows are left out of that tree.

Press "Draw 200 samples": the orange dots cluster around the curve, and the average settles near the theory value.

A free test set: the out-of-bag (OOB) score. Because every tree has about a third of the rows it never saw, we can test each row using only the trees that did not train on it, and average the results. That gives an honest accuracy estimate without a separate validation set and without cross-validation. In scikit-learn it is one flag: oob_score=True.

3. Ingredient 2: random features at every split

Bootstrap alone is not enough. Suppose one feature is very strong (say "worst perimeter" for tumours). Every tree, whatever rows it got, would put that feature at the top, and the trees would end up nearly identical. Averaging near-identical trees achieves nothing.

So at every split, a tree is only allowed to consider a random subset of max_features features, and picks the best split among those only. Sometimes the strong feature is not in the subset, and the tree is forced to find another good question. That makes the trees different, and the "different" trees make different mistakes.

SettingMeaning
max_features="sqrt"Consider √(number of features) at each split. The default for classification. With 30 features: 5.
max_features=1.0Consider all features (the default for the regressor). Then only the bootstrap makes trees different.
small number (e.g. 1)Very different trees, but each is individually weaker. More randomness = less correlation, but a bit more bias.

4. Ingredient 3: why voting works (with numbers)

Voting by hand

Suppose each tree, independently, is right 70% of the time, and we ask an odd number of trees to vote (so no ties).

3 trees: the majority is right if at least 2 are right. Three right: 0.7³ = 0.343. Exactly two right (there are 3 ways): 3 × 0.7² × 0.3 = 0.441. Total = 0.784, already above 0.70.

The catch: independence. These numbers assume the trees make independent mistakes. Real trees trained on the same data are partly correlated (they tend to be wrong about the same hard rows). In words, the variance of an average of n predictions is:

variance of the average = ρ × σ² + (1 − ρ) × σ² ÷ n

where σ² is the variance of one tree and ρ (rho, from 0 to 1) is how correlated the trees are. Take σ² = 1:

Two lessons: (a) more trees always helps, but with diminishing returns: the second term shrinks towards zero and you are left with ρ × σ². (b) The only way to push below that floor is to lower ρ, that is, to make the trees less alike. That is exactly the job of the bootstrap and the random feature subsets.

Set "Copying between trees" to 0 and drag the number of trees up: accuracy climbs towards 100%. Raise the copying and the curve flattens at a ceiling well below 100%. (The copying model here is a simple illustration: with that probability every tree copies one shared answer, otherwise they vote independently.)

To keep the arithmetic short we grow a forest of three one-question trees ("stumps"). (A real forest has deep trees and 100+ of them, but the mechanics are identical.) Each tree gets a bootstrap sample and a randomly chosen feature; it picks the threshold with the lowest weighted Gini (see the Decision Tree lesson).

Tree 1 · sample: rows 1, 2, 4, 4, 6, 7, 7, 8 · feature allowed: study hours. The sample's labels are 0, 0, 1, 1, 1, 1, 1, 1: six Pass, two Fail, so Gini = 1 − 0.75² − 0.25² = 0.375. Best threshold: study ≤ 3 → left {0, 0} (Gini 0), right {1,1,1,1,1,1} (Gini 0), weighted Gini = 0. Rule: study ≤ 3 → Fail, else Pass. Out-of-bag rows: 3 and 5.

Tree 2 · sample: rows 1, 3, 3, 5, 6, 6, 8, 8 · feature allowed: sleep hours. Labels 0,0,0,0,1,1,1,1 → Gini 0.5. The sleep values are 6,5,5,4,6,6,5,5, so the best threshold is sleep ≤ 4.5: left {row 5: Fail} (Gini 0), right 7 rows (3 Fail, 4 Pass), Gini = 1 − (4/7)² − (3/7)² = 0.490. Weighted = (1/8) × 0 + (7/8) × 0.490 = 0.429. Rule: sleep ≤ 4.5 → Fail, else Pass. (A weak tree: sleep is not very informative.) Out-of-bag rows: 2, 4 and 7.

Tree 3 · sample: rows 2, 3, 4, 5, 5, 6, 7, 8 · feature allowed: study hours. Labels 0,0,1,0,0,1,1,1 → Gini 0.5. Best threshold study ≤ 5.5: left 5 rows {0,0,1,0,0}, Gini = 1 − 0.2² − 0.8² = 0.32; right {1,1,1}, Gini 0; weighted = (5/8) × 0.32 + 0 = 0.200. Rule: study ≤ 5.5 → Fail, else Pass. Out-of-bag row: 1.

Feature importance

A forest can also tell you which features mattered: add up how much impurity each feature's splits removed. Here study hours removed 0.375 (Tree 1) + 0.300 (Tree 3, from 0.5 to 0.2) = 0.675; sleep removed 0.5 − 0.429 = 0.071. Study hours clearly matters far more. (scikit-learn rescales each tree and averages, but the idea is exactly this.)

6. The forest on curved data

Now the full thing on two half-moon-shaped classes, with deep trees. The right-hand chart is the payoff: as trees are added, the test accuracy (orange line) climbs and settles down, while the training accuracy stays high. The dashed line is the OOB accuracy, computed without using any test points.

class Aclass Bfilled = training · hollow = test · shading = the forest's average vote · lines: blue = training accuracy, orange = test accuracy, green dashed = out-of-bag accuracy
  • Switch to "tree #1 alone": jagged islands wrapped around individual points. Now switch back to the forest: the same kind of trees, averaged, give a much smoother boundary.
  • Drag the number of trees from 1 to 100: accuracy rises quickly at first, then flattens. Adding trees never makes a random forest overfit more; it only stops helping. (Depth, not the number of trees, is what controls overfitting.)
  • Turn bootstrap off and set max_features to "2 of 2": every tree is now identical. The forest collapses into one tree. This is the correlation problem from section 4, made visible.
  • Lower the depth to 1 or 2: the trees are too simple and the forest inherits that (underfitting). Forests love deep, unpruned trees, because averaging removes the overfitting.

7. Regression: averaging away the staircase

For a numeric target every tree predicts a number (the average of its leaf) and the forest predicts the average of the trees' numbers. A single regression tree gives a jagged staircase; the average of many staircases with steps in different places is a much smoother curve.

Compare "a typical single tree" with "the forest average" in the readout. The forest is nearly always noticeably better. One honest limitation to notice too: a forest can only predict values inside the range it has seen, because every leaf is an average of training targets. It cannot extrapolate a trend beyond the data the way a straight line can.

8. Random Forest in scikit-learn

Our hand example first (with 100 trees, not 3; the trees are random, so exact numbers depend on random_state):

from sklearn.ensemble import RandomForestClassifier

X = [[1, 6], [2, 8], [3, 5], [4, 7], [5, 4], [6, 6], [7, 8], [8, 5]]   # study, sleep
y = [0, 0, 0, 1, 0, 1, 1, 1]

rf = RandomForestClassifier(n_estimators=100, random_state=0).fit(X, y)

print(rf.predict([[5, 7]]))         # [1]  -> Pass
print(rf.predict_proba([[5, 7]]))   # [[0.2 0.8]]   -> 80% of the average leaf probability says Pass
print(rf.predict_proba([[2.5, 4]])) # [[0.96 0.04]] -> very likely Fail

Now the realistic recipe on a real dataset: compare one tree with a forest, use the free OOB score, and read the feature importances. (The output comments below are from an actual run with scikit-learn 1.9.0; other versions may differ slightly.)

from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split, cross_val_score
from sklearn.tree import DecisionTreeClassifier
from sklearn.ensemble import RandomForestClassifier

data = load_breast_cancer()
X, y = data.data, data.target
X_train, X_test, y_train, y_test = train_test_split(X, y, stratify=y, random_state=42)

tree = DecisionTreeClassifier(random_state=42).fit(X_train, y_train)
print(tree.score(X_train, y_train), tree.score(X_test, y_test))   # 1.0   0.923  (memorised)

rf = RandomForestClassifier(n_estimators=200, oob_score=True,
                            random_state=42, n_jobs=-1).fit(X_train, y_train)
print(rf.score(X_train, y_train), rf.score(X_test, y_test))       # 1.0   0.958
print(rf.oob_score_)                                              # 0.962  (free, no test set used)

# which features mattered most?
top = sorted(zip(rf.feature_importances_, data.feature_names), reverse=True)[:3]
print(top)   # worst perimeter (0.146), worst area (0.137), worst concave points (0.107)

# cross-validated comparison on all the data
print(cross_val_score(DecisionTreeClassifier(random_state=42), X, y, cv=5).mean())          # 0.917
print(cross_val_score(RandomForestClassifier(n_estimators=200, random_state=42), X, y, cv=5).mean())  # 0.958

Both models score 100% on the training data, yet the forest is clearly better on unseen data, which is the whole point of averaging. A forest needs no feature scaling (like a tree, it only compares values to thresholds), copes with a mix of numeric and (encoded) categorical columns, and works well with default settings. Regression is the same with RandomForestRegressor:

from sklearn.datasets import load_diabetes
from sklearn.ensemble import RandomForestRegressor
from sklearn.tree import DecisionTreeRegressor
from sklearn.metrics import r2_score

Xd, yd = load_diabetes(return_X_y=True)
Xtr, Xte, ytr, yte = train_test_split(Xd, yd, random_state=0)

print(r2_score(yte, DecisionTreeRegressor(random_state=0).fit(Xtr, ytr).predict(Xte)))   # -0.18  (worse than guessing the mean!)
print(r2_score(yte, RandomForestRegressor(n_estimators=200, random_state=0).fit(Xtr, ytr).predict(Xte)))  # 0.25

The diabetes data is noisy, so even the forest reaches only R² ≈ 0.25, but the jump from a negative R² (a single deep tree) to a positive one shows what averaging does.

9. Strengths, limits and real-world use

StrengthsLimits
Excellent accuracy with almost no tuning: a superb first model for tabular dataLess interpretable than one tree: you cannot draw "the" tree any more
Resists overfitting; more trees never hurtsBig models: hundreds of deep trees use memory and are slower to predict than a linear model
No scaling needed; handles non-linear patterns and feature interactionsCannot extrapolate beyond the range of the training targets
Built-in OOB score and feature importancesWeaker than linear models on very sparse, high-dimensional data such as raw text
Robust to outliers and noisy features; trains in parallelBoosting methods (next lessons) often edge it out when carefully tuned

🏦 Credit scoring and fraud

Banks combine hundreds of transaction and account features into a risk score. Forests handle the messy mix of columns with little preparation.

🏥 Medical prediction

Predicting disease risk or readmission from lab results and history, and ranking which measurements mattered.

🛒 Customer churn and recommendation

Which customers are about to leave? A forest on usage data is a common, dependable baseline.

🌍 Remote sensing

Classifying land cover (forest, water, crops) from satellite bands, one of the classic large-scale uses.

🎮 Body tracking

Kinect-style body-part recognition famously used forests of depth-comparison trees, chosen because they are very fast at prediction time.

🔎 Feature selection

Even if the final model is something else, forest importances are a quick way to see which inputs carry signal.

Key takeaways

  • A random forest = many decorrelated deep trees + a vote. Deep single trees have high variance; averaging cancels it.
  • Bootstrap: each tree trains on a with-replacement sample; about 63.2% of distinct rows are in, about 36.8% are out-of-bag.
  • Random features per split (max_features, default √features for classification) keep the trees different. Variance of the average = ρσ² + (1 − ρ)σ²/n: more trees shrink the second term, less correlation lowers the first.
  • The OOB score is a free, honest accuracy estimate; feature_importances_ shows which features carry the signal.
  • More trees never overfit; depth and leaf size control overfitting. No scaling needed. Great default for tabular data.
  • Limits: less interpretable, cannot extrapolate, and bigger than one tree.
