XGBoost

XGBoost ("eXtreme Gradient Boosting") is gradient boosting with two upgrades: a built-in penalty for over-complicated trees, and a smarter way of choosing splits that uses a little more information about the loss. Add a lot of engineering for speed and you get one of the most widely used tools for table-shaped data.

1. The big idea: gradient boosting with a leash

You already know the core loop from the last lesson: start with a guess, and add small trees that correct what is left over. XGBoost keeps that loop and changes how each tree is built.

The golfer gets a coach. In plain gradient boosting the golfer takes every corrective shot as advised. XGBoost adds a coach with two rules: "don't make the swing more complicated than it needs to be" (a price for every extra leaf, called γ) and "don't trust a suggestion built on only a couple of shots" (shrink the size of each correction, called λ). The coach also brings a stopwatch: XGBoost is engineered to search for splits quickly and to use all your CPU cores.

2. The maths in plain words

XGBoost tries to minimise (how wrong the model is) + (a penalty for how complicated the trees are). The penalty adds up two things: γ for each leaf, and a term that grows with the size of the leaf values (controlled by λ). Everything else follows from a bit of algebra, which we skip. What you need to know are four simple recipes.

Two numbers per training point. For each point, given the current prediction:

  • g, the gradient: which way and how far the prediction is off. For squared error, g = prediction − actual. For classification, g = p − y (p is the predicted probability, y is 0 or 1).
  • h, the hessian: how "curved" the loss is there, roughly how much the loss cares. For squared error, h = 1 for every point. For classification, h = p × (1 − p): large when the model is unsure (p near 0.5), tiny when it is already confident.

Add up g and h over the points in a group of points (a leaf): G = Σg, H = Σh. Then:

  1. Leaf value (what the leaf adds to the prediction) = −G ÷ (H + λ). Without λ this is just the average residual. With λ, small groups (small H) are pulled strongly towards 0.
  2. Similarity score of a group = G² ÷ (H + λ). High when the group's points all want to be corrected in the same direction.
  3. Gain of a split = (similarity of left) + (similarity of right) − (similarity of the group before splitting) − γ.
  4. Build the tree by taking the split with the biggest gain. If the best gain is not above 0 after subtracting γ, don't split ("pruning"). Finally the prediction is updated by eta × leaf value (eta = learning rate).

The best cut is x ≤ 3.5 (gain 55.13). Leaf values: left = −10.5 ÷ (3 + 1) = −2.625, right = +10.5 ÷ 4 = +2.625. Notice these are smaller than the plain residual averages (−3.5 and +3.5): λ has shrunk them by a factor 3 ÷ 4. With eta = 0.5 each prediction moves by half of that: 6.5 − 1.3125 = 5.1875 for x = 1 to 3 and 6.5 + 1.3125 = 7.8125 for x = 4 to 6. MSE = 5.45.

Round 2. New g = prediction − y: 3.19, 1.19, 2.19, −1.19, −3.19, −2.19. Again x ≤ 3.5 wins (gain 21.53), leaf values ∓ 6.5625 ÷ 4 = ∓1.6406. With eta 0.5: predictions 4.367 and 8.633, MSE = 2.54.

Round 3. Same split, leaf values ∓1.0254, predictions 3.854 and 9.146, MSE = 1.40.

Compared with plain gradient boosting (MSE 3.73 → 1.43 → 0.72 for the same three rounds), XGBoost moves more cautiously: that is λ at work. On six noise-free-looking points this just looks slower, but on real, noisy data that caution is exactly what stops trees from overreacting to a few odd points.

The price of a leaf: γ. The winning split had a gain of 55.13. If we set γ = 50, the split's net worth is 5.13 and it is kept. If γ = 60, its net worth is negative, so the tree refuses to split at all and stays a single leaf that adds nothing. (I ran this in XGBoost: γ = 50 keeps the split, γ = 60 gives a tree with no splits.) γ therefore acts as a threshold: only make a split if it improves the objective by more than γ.

Classification by hand

Labels 0, 0, 1, 1, 0, 1 for x = 1 to 6. Start: p = 0.5 for every point (score 0). Then g = p − y = +0.5, +0.5, −0.5, −0.5, +0.5, −0.5 and h = 0.5 × 0.5 = 0.25 for every point. Use λ = 1, eta = 1.

Gains for the five cuts (using G²÷(H+1) on each side): x ≤ 1.5 → 0.31; x ≤ 2.5 → 1.17; x ≤ 3.5 → 0.29; x ≤ 4.5 → 0; x ≤ 5.5 → 0.31. The best is x ≤ 2.5:

  • Left (points 1, 2): G = 1, H = 0.5 → value = −1 ÷ (0.5 + 1) = −0.667.
  • Right (points 3 to 6): G = −1, H = 1 → value = +1 ÷ (1 + 1) = +0.5.

As probabilities: 1 ÷ (1 + e0.667) = 0.339 for points 1 and 2, and 1 ÷ (1 + e−0.5) = 0.622 for points 3 to 6. Plain gradient boosting on the same data gave −2 and +1 (probabilities 0.119 and 0.731): XGBoost's λ makes the first step much gentler.

A real gotcha: min_child_weight. This parameter demands a minimum sum of h in every leaf (default 1). For squared error h = 1 per point, so it means "at least one point". But for classification h = p(1 − p) is at most 0.25, so a leaf needs several points, and in our tiny example the left leaf has H = 0.5 < 1. With the default setting XGBoost refuses the split, and the model learns nothing (I ran it: a single leaf with value 0). To reproduce the hand calculation I had to set min_child_weight=0. On real datasets with hundreds of rows this rarely matters, but it is a common cause of "my tiny test model does nothing".

4. Why it is fast: the engineering

  • Histogram splits (tree_method="hist", the default in recent versions): instead of trying a cut between every pair of values, group each feature into a few hundred bins and try only the bin edges. Far fewer candidate splits, almost the same accuracy.
  • Parallel split search: although trees are built one after another, the search for the best cut across features and bins can use all CPU cores (or a GPU).
  • Column and row subsampling: colsample_bytree and subsample use only a random fraction of the features and rows for each tree, adding random-forest-like diversity and speed.
  • Sparsity-aware splits: for each split XGBoost tries sending missing values left and right and remembers the direction that lowers the loss. You can leave NaNs in the data.
  • Early stopping and built-in evaluation: watch a validation set during training and stop when it stops improving.

5. XGBoost in Python

XGBoost is a separate library (pip install xgboost), not part of scikit-learn, but its XGBClassifier and XGBRegressor follow the scikit-learn interface (fit, predict, pipelines, GridSearchCV). The results below come from an actual run with XGBoost 3.4.1 and scikit-learn 1.9.0; other versions may differ.

First, our worked example (settings chosen to match the hand calculation):

import numpy as np
import xgboost as xgb

X = np.arange(1, 7).reshape(-1, 1).astype(float)
y = np.array([2, 4, 3, 9, 11, 10.])

m = xgb.XGBRegressor(n_estimators=3, max_depth=1, learning_rate=0.5,
                     reg_lambda=1, gamma=0, base_score=6.5,
                     tree_method="exact").fit(X, y)

booster = m.get_booster()
for k in (1, 2, 3):        # prediction after k trees
    print(booster.predict(xgb.DMatrix(X), iteration_range=(0, k)).round(4))
# [5.1875 5.1875 5.1875 7.8125 7.8125 7.8125]
# [4.3672 4.3672 4.3672 8.6328 8.6328 8.6328]
# [3.8545 3.8545 3.8545 9.1455 9.1455 9.1455]   -> all match the hand calculation

The tree dump shows exactly the split (x < 3.5), gain (55.125) and leaf values we computed. Now the realistic recipe: a real dataset, row and column subsampling, and early stopping on a validation slice.

import xgboost as xgb
from sklearn.datasets import load_breast_cancer
from sklearn.model_selection import train_test_split

X, y = load_breast_cancer(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(X, y, stratify=y, random_state=42)

clf = xgb.XGBClassifier(random_state=42).fit(X_train, y_train)     # defaults
print(clf.score(X_test, y_test))                                   # 0.965

X_fit, X_val, y_fit, y_val = train_test_split(X_train, y_train, test_size=0.2,
                                              stratify=y_train, random_state=0)
clf = xgb.XGBClassifier(n_estimators=1000, learning_rate=0.05, max_depth=3,
                        subsample=0.8, colsample_bytree=0.8,
                        early_stopping_rounds=20, eval_metric="logloss", random_state=42)
clf.fit(X_fit, y_fit, eval_set=[(X_val, y_val)], verbose=False)
print(clf.best_iteration, clf.score(X_test, y_test))               # 581 trees, 0.965

# missing values: blank out 10% of the entries in train AND test, no imputation
# (this run: 0.965 again, the splits learned where to send the missing values)

Cross-validated accuracy of the default model was 0.970 (5-fold), against 0.963 for scikit-learn's gradient boosting and 0.958 for the random forest. On a dataset this small and easy those gaps are only a few rows, so don't over-read them. It is on harder problems that tuning matters, as the noisy diabetes regression shows (R² on the same split as earlier lessons):

xgb.XGBRegressor(random_state=0)                                    # defaults: R² = 0.049

# for comparison on the same split: random forest 0.250, tuned gradient boosting 0.315

Default XGBoost is a poor fit for this tiny, noisy dataset (it uses deep, fast-learning trees), and careful settings fix that. Boosting libraries reward tuning, and the tuned scikit-learn gradient boosting model did just as well.

ParameterWhat it does
n_estimatorsNumber of boosting rounds. Set it high and rely on early_stopping_rounds.
learning_rate (eta)Shrinks each tree's contribution (default 0.3). Lower (0.01 to 0.1) with more rounds is the usual best practice.
max_depthDepth of each tree (default 6). Try 3 to 6; shallower for small or noisy data.
min_child_weightMinimum sum of h in a leaf (default 1). Raise it to forbid leaves built on very few points.
gammaMinimum gain needed to split (default 0). Raise to prune weak splits.
reg_lambda, reg_alphaL2 (default 1) and L1 (default 0) penalties on the leaf values. λ is the one in this lesson; α pushes small leaf values to exactly 0.
subsample, colsample_bytreeFraction of rows and of features used per tree. 0.6 to 1.0 is typical.
tree_method"hist" (fast, default in recent versions), "exact" (checks every cut), "approx".
scale_pos_weightUp-weights the positive class in imbalanced binary problems (a common choice: number of negatives ÷ number of positives).
early_stopping_rounds, eval_set, eval_metricStop when the validation metric has not improved for that many rounds; best_iteration records where.
objectiveThe loss: reg:squarederror, binary:logistic, multi:softprob, ranking objectives and more (set automatically by the classifier and regressor classes).
feature_importances_Importance per feature (in the breast-cancer run above, "worst radius" took about 52%).

A sensible tuning order: fix learning_rate (0.05 to 0.1), find n_estimators by early stopping, then tune max_depth and min_child_weight, then subsample and colsample_bytree, then gamma and reg_lambda, and finally lower the learning rate and retrain. A grid or random search with cross-validation is the tool for the middle steps, which is our next lesson.

6. Strengths, limits and real-world use

StrengthsLimits
Excellent accuracy on tabular data, often the top performerMany hyperparameters; defaults are not always good (see the diabetes example)
Built-in regularisation and early stoppingCan still overfit noisy labels if trees are deep and rounds too many

🏆 Competitions

XGBoost became famous by winning many tabular-data contests, and it is still a standard first serious model to try.

🏦 Fraud and credit risk

Millions of transactions, hundreds of mixed features, missing values everywhere: exactly what it was built for.

📈 Click-through and ranking

Ranking objectives order search results or ads; log-loss models estimate click probabilities.

🏭 Predictive maintenance

Sensor readings and service history predict which machine fails next; scale_pos_weight handles the rarity of failures.

🛍️ Demand forecasting

Turn dates, prices and promotions into features and predict sales for each item and store.

🧬 Genomics and medicine

Risk models from lab values and gene measurements, with feature importances to guide follow-up.

Key takeaways

  • XGBoost = gradient boosting whose trees are built from g (gradient) and h (hessian) with a built-in penalty on complexity.
  • Leaf value = −G ÷ (H + λ). Similarity = G² ÷ (H + λ). Gain = left + right − parent − γ. Do not split when the gain is not above 0 after γ.
  • λ shrinks leaf values (small groups most); γ is the price of a leaf; min_child_weight sets a minimum amount of "h" per leaf, and it can block tiny classification trees.
  • Worked example: the same six points as plain boosting give a more cautious 5.45 → 2.54 → 1.40 (vs 3.73 → 1.43 → 0.72), and XGBoost reproduced every number.
  • Speed comes from histogram splits, parallel search, subsampling, sparsity-aware missing-value handling and GPU support.
  • Tune with a small learning rate, many trees and early stopping; defaults are a starting point, not an answer.

1. λ = 1: 6² ÷ (3 + 1) = 36 ÷ 4 = 9. λ = 0: 36 ÷ 3 = 12. A larger λ lowers the similarity score (and the leaf value), so the group looks less convincing: this is the shrinkage.

2. Leaf value = −G ÷ (H + λ) = 12 ÷ 6 = 2. With eta 0.3 it adds 0.3 × 2 = 0.6.

3. Left similarity = 64 ÷ 5 = 12.8, right = 64 ÷ 3 = 21.33, parent = 0. Gain = 12.8 + 21.33 − 0 = 34.13 (this is the x ≤ 4.5 cut from the worked example). With γ = 40: 34.13 − 40 = −5.87, which is not above 0, so the split is pruned.

4. g = p − y = 0.8 − 1 = −0.2 (the model should push the score up a little). h = p(1 − p) = 0.8 × 0.2 = 0.16.

5. Small changes are typical on such an easy dataset (test accuracy is usually within a row or two), but a larger gamma or reg_lambda usually gives simpler trees and may change how many rounds early stopping needs. Results depend on your versions.
