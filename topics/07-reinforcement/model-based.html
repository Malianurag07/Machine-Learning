Reinforcement Learning: Model-Based Methods

In reinforcement learning (RL) an agent learns what to do by trying things and receiving rewards, instead of being shown correct answers. Model-based methods start from a simple idea: if you know how the world works, you can plan, working out the best behaviour by calculation before taking a single risky step. This lesson introduces the RL vocabulary, then the two classic planning algorithms, value iteration and policy iteration.

1. The big idea: learning from rewards

In supervised learning every example comes with the right answer. In RL there is no answer key. An agent acts in an environment; after each action the environment moves to a new situation and gives back a number, the reward (positive is good, negative is bad). The agent's goal is to collect as much reward as possible over time. The catch: the consequences of an action can arrive much later (a chess move, a turn in a maze), and the agent's own actions decide what data it sees next.

Finding your way in a new city. You want to reach a café. A model-based traveller studies a map first: which streets connect, how long each takes, where the roads are closed. With the map, she plans the whole route on paper and only then sets off. A model-free traveller has no map and learns by wandering, remembering which turns paid off. This lesson is about the map-reader; the next lesson is about the wanderer. The "map" in RL is called the model.

The return and the discount

A reward now is worth more than the same reward much later (it may never come, and waiting has costs). The discount factor γ (gamma, between 0 and 1) expresses this: a reward received k steps in the future counts γk times as much. The return is

G = r₁ + γ r₂ + γ² r₃ + γ³ r₄ + …

Example with γ = 0.9: rewards −1, −1, +10 over three steps give G = −1 + 0.9 × (−1) + 0.9² × 10 = −1 − 0.9 + 8.1 = 6.2. The same +10 reward received ten steps later would be worth only 10 × 0.910 = 3.49. With γ near 0 the agent is short-sighted (only immediate rewards matter); with γ near 1 it is far-sighted.

2. The Markov decision process (MDP)

Most of RL theory uses one mathematical setting, the Markov decision process, which has five ingredients:

  • a set of states S and a set of actions A,
  • the transition probabilities P(s′ | s, a): if the agent takes action a in state s, the chance of ending up in state s′ (the world can be uncertain: a wheel slips, a die is rolled),
  • the rewards R(s, a, s′),
  • the discount γ.

"Markov" means the future depends only on the current state and action, not on the earlier history: the state contains everything you need to know. P and R together are the model of the environment.

Value functions: how good is a state?

To choose well, the agent needs to know how promising each state is. The value of a state under a policy, Vπ(s), is the return the agent can expect if it starts in s and follows π. The action value Qπ(s, a) is the expected return if it takes action a first, and follows π afterwards. The best achievable values are V* and Q* ("optimal"), and a policy that acts greedily with respect to Q* is optimal.

The Bellman equation (the key identity of RL). The value of a state is the expected immediate reward plus the discounted value of where you end up:

Q(s, a) = Σs′ P(s′ | s, a) × [ r + γ × V(s′) ]    and    V*(s) = the largest Q*(s, a) over the actions a

In words: "Look one step ahead: average over what might happen, add the reward you get, add the (discounted) value of the next state, and pick the best action." The values of neighbouring states are tied together by this equation, and solving these equations solves the whole problem.

4. Value iteration

Value iteration finds the optimal values by applying the Bellman equation over and over as an update:

  1. Start with V(s) = 0 for every state (terminal states keep the value of their reward).
  2. Sweep: for every state s, compute Q(s, a) for each action a from the current values, and set the new V(s) to the largest one.
  3. Repeat the sweep until the values stop changing.
  4. Read off the policy: in every state, the action with the largest Q.

Each sweep pushes information one step further through the state space: rewards near the prizes spread outward like ripples until the values are consistent everywhere. It is guaranteed to converge (for γ < 1) to the optimal values.

By hand: a robot in a corridor

A corridor of five cells: [small prize 5] – s1 – s2 – s3 – [big prize 10]. The robot can try to move left or right. Moves are unreliable: with probability 0.8 it moves in the intended direction, and with probability 0.2 it slips and moves the other way. Every step costs 1 (reward −1). Reaching either end ends the episode with the prize. γ = 0.9. Terminal states have a fixed value equal to their prize (5 and 10), and s1, s2, s3 start at 0.

Sweep 1 (uses V = 5, 0, 0, 0, 10):

  • s1: going left: 0.8 × (−1 + 0.9 × 5) + 0.2 × (−1 + 0.9 × 0) = 0.8 × 3.5 − 0.2 = 2.6. Going right: 0.8 × (−1 + 0) + 0.2 × (−1 + 4.5) = −0.8 + 0.7 = −0.1. Best: left, V(s1) = 2.6.
  • s2: both directions lead to states with value 0: −1 whichever way. V(s2) = −1.
  • s3: going right: 0.8 × (−1 + 0.9 × 10) + 0.2 × (−1 + 0) = 6.4 − 0.2 = 6.2. Going left is worse (0.8). V(s3) = 6.2.

Sweep 2 (uses V = 5, 2.6, −1, 6.2, 10). For instance s2: going right: 0.8 × (−1 + 0.9 × 6.2) + 0.2 × (−1 + 0.9 × 2.6) = 0.8 × 4.58 + 0.2 × 1.34 = 3.664 + 0.268 = 3.932; going left is only 1.988. So V(s2) = 3.932. The other two: V(s1) = 2.42, V(s3) = 6.02.

5. Policy iteration

Value iteration improves the values directly and reads the policy off at the end. Policy iteration alternates two steps that work on a policy:

  1. Policy evaluation: for the current policy π, compute how good it is: the values Vπ (by solving the Bellman equations for π: no maximisation, just follow the policy's action in each state; or by sweeping until they stop changing).
  2. Policy improvement: in every state, switch to the action with the largest Q under those values. (If nothing changes, π is optimal and we stop.)

Each improvement can only make the policy better (or leave it unchanged), and there are finitely many policies, so it terminates at the optimal one, usually in only a few rounds.

On our corridor. Start with the naive policy "always right". Evaluate: Vπ = 3.249, 4.652, 7.037 for s1, s2, s3. Improve: at s1, going left is worth 0.8 × (−1 + 0.9 × 5) + 0.2 × (−1 + 0.9 × 4.652) = 2.8 + 0.637 = 3.437 compared with 3.249 for going right: switch to left. At s2 and s3 the right action is still best (s2: 4.652 vs 2.606; s3: 7.037 vs 4.149). New policy: left, right, right.

Evaluate again: Vπ = 3.445, 4.692, 7.045. Improve: nothing wants to change. Done after 2 rounds: the same optimal policy value iteration found (I checked with a program). Value iteration needed about 10 sweeps for the same accuracy.

6. A bigger world: the classic 4 × 3 grid

The same ideas, on the standard textbook example. The agent starts at the bottom left. The top-right cell is a goal (+1), the cell below it a pit (−1), and the grey cell is a wall. Each move has an 80% chance of going the intended way and 10% each of slipping to the left or right of it (bumping into a wall or the edge leaves the agent where it is). Each step costs 0.04.

  • Press "Run to convergence" with the default settings: the values match the textbook (0.812, 0.868, 0.918 in the top row; 0.705, 0.655, 0.611, 0.388 in the bottom row). Notice the route: the agent goes up the left side and along the top, the longer way, to stay away from the pit: it is worth walking further to avoid a 10% chance of slipping into −1.
  • "Compare over 1000 episodes": the average return of the planned policy matches the value predicted for the start cell, while random moves earn far less. The value function really is a prediction of the return.
  • Cost per step shapes the behaviour. At −2 per step the agent hurries to end the episode, even into the pit. With a small positive reward per step (+0.05) it avoids the ends entirely and wanders around collecting reward. Designing the reward is half the art of RL.
  • Slip probability 0: there is no risk any more, so no detour is needed: a shortest path of 5 steps works (there are two), and the value of the start cell becomes exactly 1 − 5 × 0.04 = 0.800.

7. Planning in code

Value iteration needs only the model (P and R) and a few lines of code. This version reproduces the grid above with NumPy (run in my environment; the printed values are the textbook values):

import numpy as np

ROWS, COLS, WALL = 3, 4, (1, 1)
TERMINAL = {(0, 3): 1.0, (1, 3): -1.0}
ACTIONS = [(-1, 0), (1, 0), (0, -1), (0, 1)]          # up, down, left, right
LIVING, GAMMA, SLIP = -0.04, 1.0, 0.2

def move(r, c, a):                                     # deterministic move, bump into walls and edges
    nr, nc = r + a[0], c + a[1]
    return (r, c) if not (0 <= nr < ROWS and 0 <= nc < COLS) or (nr, nc) == WALL else (nr, nc)

def outcomes(a):                                       # the model: (probability, actual move)
    side = [(0, -1), (0, 1)] if a[0] != 0 else [(-1, 0), (1, 0)]
    return [(1 - SLIP, a), (SLIP / 2, side[0]), (SLIP / 2, side[1])]

V = np.zeros((ROWS, COLS))
for (r, c), reward in TERMINAL.items(): V[r, c] = reward
for sweep in range(500):
    new = V.copy()
    for r in range(ROWS):
        for c in range(COLS):
            if (r, c) in TERMINAL or (r, c) == WALL: continue
            new[r, c] = max(sum(p * (LIVING + GAMMA * V[move(r, c, act)]) for p, act in outcomes(a)) for a in ACTIONS)
    V = new
print(V.round(3))
# [[ 0.812  0.868  0.918  1.   ]
#  [ 0.762  0.     0.66  -1.   ]
#  [ 0.705  0.655  0.611  0.388]]

Now a standard benchmark with a built-in model: FrozenLake from the gymnasium library (pip install gymnasium). A 4 × 4 frozen lake: reach the goal without falling into a hole; the ice is slippery, so the robot moves in the intended direction only a third of the time (it slips to either side otherwise). The environment exposes its full model as env.unwrapped.P[state][action], a list of (probability, next state, reward, done). All results below are from an actual run (gymnasium 1.3.0):

import gymnasium as gym, numpy as np
env = gym.make("FrozenLake-v1", is_slippery=True)
P, nS, nA = env.unwrapped.P, 16, 4                     # P[s][a] = [(prob, next_state, reward, done), ...]

def q_values(V, gamma):
    return np.array([[sum(p * (r + gamma * V[s2] * (not done)) for p, s2, r, done in P[s][a]) for a in range(nA)] for s in range(nS)])

V = np.zeros(nS)
while True:                                            # value iteration
    V_new = q_values(V, 0.99).max(axis=1)
    if np.abs(V_new - V).max() < 1e-10: break
    V = V_new
policy = q_values(V, 0.99).argmax(axis=1)
print(V.reshape(4, 4).round(3)[0])                     # [0.542 0.499 0.471 0.457]   value of the start cell: 0.542
print(policy.reshape(4, 4))                            # [[0 3 3 3] [0 0 0 0] [3 1 0 0] [0 2 1 0]]   0=left 1=down 2=right 3=up

# how good is the plan? run it in the real environment
# success rate of the planned policy: 74.8% (10,000 episodes; the environment stops an episode after 100 steps)
# success rate of random actions:       1.3% (5,000 episodes)
# without the 100-step limit the exact success probability of the planned policy is 82.4%
# policy iteration reaches exactly the same policy, in 7 rounds of evaluate + improve

With the plan the robot reaches the goal about three times in four; with random actions, one time in eighty. Notice something surprising in the policy printed above: in the top row it says "up" (3) and "left" (0), i.e. it walks into walls on purpose. On slippery ice, pushing against the edge is the safest way to shuffle sideways without slipping into a hole. That is planning under uncertainty at work.

8. When the model is not known: learn it, then plan

Real environments rarely come with P and R. The model-based answer is to learn the model from experience, then plan with it:

  1. Explore: take actions and record every transition (s, a, r, s′).
  2. Estimate the model by counting: P̂(s′ | s, a) = (times action a in state s led to s′) ÷ (times a was tried in s); R̂ likewise as the average reward seen.
  3. Plan with the estimated model, exactly as in sections 4 to 7 (this is sometimes called certainty equivalence: act as if the estimate were the truth).
  4. Keep exploring, updating the counts and re-planning as the model improves.

A tiny example: the robot tries "right" from s2 twenty times and observes 15 successes (moves right) and 5 slips (moves left). It estimates P̂(right → success) = 15 ÷ 20 = 0.75 (true value 0.8) and plans with that.

On FrozenLake I tested it: the agent moves around with purely random actions for N steps, learns P̂ and R̂ from the counts, plans with value iteration, and the resulting policy is evaluated exactly in the real lake (the best possible value at the start is 0.542; average of 5 runs):

Ideas built on this

  • Dyna: mix real experience with imagined experience generated from the learned model, so each real step is used many times.
  • Planning at decision time: instead of solving for every state in advance, search forward from the current state with the model (Monte-Carlo tree search, model-predictive control). This is how game-playing systems and many robot controllers work.
  • Learned neural-network models: for large problems the model (and value function) are neural networks. Famous game systems combine a model with tree search, learning values and policies as they go.

9. Strengths, limits and real-world use

StrengthsLimits
Very efficient with data once the model is good: planning costs computation, not real-world trialsNeeds a model: exact (a game's rules) or learned. Errors in the model become errors in the plan
The model can be reused for new goals (change the reward and re-plan)Dynamic programming sweeps every state: infeasible for huge or continuous state spaces without approximation
Can plan safely "in simulation" before actingComplex worlds (images, other people) are hard to model accurately
Transparent: values and plans can be inspectedUncertainty in the model must be handled carefully, or the agent can be overconfident

🎲 Board games

The rules are the perfect model: search and planning with them are the backbone of chess, Go and similar game programs.

🤖 Robotics and control

Model-predictive control plans a few seconds ahead with a physical model, replanning constantly (robot arms, drones, self-balancing machines).

📦 Inventory and operations

Stock ordering, machine maintenance and staffing are classic MDPs solved by dynamic programming: the model comes from demand statistics.

🚗 Route and motion planning

Choosing routes and manoeuvres under uncertain traffic or obstacles, from a model of how they move.

🏥 Treatment planning

Sequences of treatment decisions, planned with models of how patients respond, then checked by clinicians.

⚡ Energy systems

Battery charging and building climate control are planned with models of demand, prices and weather.

Key takeaways

  • RL: an agent takes actions in an environment, receives rewards, and learns a policy that maximises the (discounted) return G = r₁ + γr₂ + γ²r₃ + … (rewards −1, −1, +10 at γ = 0.9 give 6.2).
  • An MDP is states, actions, transition probabilities P, rewards R and γ. P and R are the model.
  • The Bellman equation: Q(s, a) = Σ P(s′|s, a) [r + γ V(s′)], and V*(s) = maxa Q*(s, a).
  • Value iteration sweeps this update until the values converge, then acts greedily. On our corridor: 2.6, −1, 6.2 → … → 3.445, 4.692, 7.045, giving the policy left, right, right.
  • Policy iteration alternates evaluating a policy and improving it; it finished in 2 rounds on the corridor and 7 on FrozenLake.
  • If the model is unknown, learn it from counts and plan with it: on FrozenLake 10,000 random steps gave 98% of the optimal value. Model errors become plan errors, so accuracy matters.
