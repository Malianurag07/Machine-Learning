Reinforcement Learning: Model-Free Methods

Last lesson, the agent had a map: the rules of the world (the model), so it could plan by calculation. Usually there is no map. Model-free methods learn directly from experience: try things, see what happens, and adjust estimates of how good each situation and action is, without ever writing down how the world works. This lesson covers the four core ideas: exploration, Monte Carlo, temporal-difference learning, and the two famous control algorithms, SARSA and Q-learning.

Intermediate≈ 100 min4 interactive demos

Recap you need. An agent takes actions in states and receives rewards; a policy maps states to actions; the return is the discounted sum of rewards (γ = discount); V(s) is the expected return from a state and Q(s, a) the expected return after taking action a in s (then continuing sensibly). If any of that is unfamiliar, read the previous lesson first.

1. The big idea: learn by doing

The food critic in a new town. You have just moved and want to eat well. You have no reviews (no model). Each evening you pick a restaurant, eat, and note how good it was. Do you go back to the place you liked last week (exploit), or try somewhere new that might be even better (explore)? And when a great meal follows a mediocre starter, how do you split the credit? Model-free RL answers exactly these two questions: how to keep score from experience, and how to balance trying new things with using what you know.

Two tasks come up again and again:

  • Prediction: given a fixed policy, estimate its values V(s). ("How good is this way of behaving?")
  • Control: find the best policy. ("What should I do?") Usually by learning Q(s, a) and acting greedily on it.

2. Exploration versus exploitation

If the agent always does what currently looks best, it may never discover something better. If it always tries random things, it never profits from what it has learned. The simplest compromise is ε-greedy:

With probability 1 − ε take the action with the highest estimated value (exploit); with probability ε take a random action (explore). Typical ε is 0.05 to 0.1, often decreasing over time.

The cleanest place to see this is the multi-armed bandit: a row of slot machines ("arms") with different, unknown average payouts. After each pull the agent updates its estimate of that arm as the running average of what it received: Q ← Q + (reward − Q) ÷ (number of pulls). Try it:

A bigger experiment, the standard "10-armed testbed" (2,000 random bandits with 10 arms each, 1,000 pulls per bandit; a run of my own code): pure greedy (ε = 0) earned on average 1.04 per pull, ε = 0.01 earned 1.20 and ε = 0.1 earned 1.31. In the last 100 pulls the greedy agent picked the best arm only 37% of the time, ε = 0.01 chose it 58% and ε = 0.1 chose it 80%. Greed gets stuck on whichever arm looked good first; a little exploration pays off handsomely.

3. Monte Carlo: average what actually happened

The simplest way to estimate a state's value is to observe it. Play a full episode, compute the return that followed each state, and average those returns over many episodes. "Monte Carlo" just means learning from random samples. No model, no bootstrapping: only real, complete outcomes.

By hand: the corridor again

The corridor from last lesson: [small prize 5] – s1 – s2 – s3 – [big prize 10]. The robot tries to move right; with probability 0.8 it goes right and with probability 0.2 it slips left. In this lesson we use the plain convention reward = −1 per move, plus the prize when a prize cell is entered (so the final step into the big prize pays −1 + 10 = +9), and γ = 0.9. Two episodes were observed:

Episode A (starting at s2): s2 → s3 (reward −1), s3 → big prize (+9). The returns: from s3: 9. From s2: −1 + 0.9 × 9 = 7.1.

Episode B (starting at s2): s2 → s3 (−1), s3 slips → s2 (−1), s2 → s3 (−1), s3 → big prize (+9). The first visit to s2: −1 + 0.9 × (−1) + 0.81 × (−1) + 0.729 × 9 = −2.71 + 6.561 = 3.851. The first visit to s3: −1 + 0.9 × (−1) + 0.81 × 9 = 5.39.

Averages so far (first-visit Monte Carlo): V(s2) ≈ (7.1 + 3.851) ÷ 2 = 5.48; V(s3) ≈ (9 + 5.39) ÷ 2 = 7.20. The true values for this policy (found by solving the equations with the full model, which the learner does not have) are 5.454 and 7.982. With just two episodes the estimates are already in the right neighbourhood, and they get better as more episodes are averaged.

Properties. Monte Carlo estimates are unbiased (they average real returns), but they are noisy (a return depends on many random events) and they can only be updated after an episode ends. They do not work for tasks that never end.

4. Temporal-difference (TD) learning: learn a little at every step

TD learning is the central idea of modern RL. Instead of waiting for the end of the episode, update after every single step, using your own current estimate of the next state as part of the target. The estimate of s is nudged towards reward + γ × (estimate of the next state):

V(s) ← V(s) + α × [ r + γ V(s′) − V(s) ]

The bracket is the TD error δ: "what I just saw (the reward plus what I now think the next state is worth) minus what I used to think this state was worth". The learning rate α (between 0 and 1) says how far to move towards the new evidence. When the next state is terminal, V(s′) = 0.

Using an estimate to update another estimate is called bootstrapping. It means information travels backward through the states as the values improve, exactly like the sweeps of value iteration, but driven by real samples instead of a model.

By hand: three steps of TD on the corridor

Start with all values 0, α = 0.5, γ = 0.9, and take the moves from episode B in order: (s3 → s2, reward −1), (s2 → s3, reward −1), (s3 → big prize, reward +9).

Step 1. s3 → s2, reward −1: δ = −1 + 0.9 × V(s2) − V(s3) = −1 + 0 − 0 = −1, so V(s3) ← 0 + 0.5 × (−1) = −0.5.

Step 2. s2 → s3, reward −1: δ = −1 + 0.9 × V(s3) − V(s2) = −1 + 0.9 × (−0.5) − 0 = −1.45, so V(s2) ← 0 + 0.5 × (−1.45) = −0.725.

Step 3. s3 → prize, reward +9, terminal: δ = 9 + 0 − V(s3) = 9 − (−0.5) = 9.5, so V(s3) ← −0.5 + 0.5 × 9.5 = 4.25.

Notice that a single big surprise (the +9) immediately raised V(s3) from −0.5 to 4.25. In the next pass through s2 → s3 that good news will flow one step back into V(s2). Monte Carlo would have had to wait for the whole episode to finish before learning anything.

And on this tiny problem the sample-average Monte Carlo (α = 1 ÷ visits) is hard to beat: don't expect TD to win everywhere. Its real advantage is that it works online, step by step, in long or endless tasks where Monte Carlo cannot even start updating.

5. Control: SARSA and Q-learning

To choose actions we learn action values Q(s, a) instead of V(s). The agent acts ε-greedily on its current Q (mostly best action, sometimes random) and after each step applies a TD update to the value of the pair it just tried. There are two classic versions, which differ in one term.

SARSA (named after the quintuple s, a, r, s′, a′ it uses):

Q(s, a) ← Q(s, a) + α × [ r + γ × Q(s′, a′) − Q(s, a) ]

where a′ is the action the agent actually takes next (including a random exploratory one). It learns the value of the policy it is actually following, mistakes and all: it is on-policy.

Q-learning:

Q(s, a) ← Q(s, a) + α × [ r + γ × maxa′ Q(s′, a′) − Q(s, a) ]

It always assumes the best next action, whatever the agent really does next. It learns the value of the greedy policy while behaving in a different, exploring way: it is off-policy, and it converges towards the optimal Q* (given enough exploration and a suitable learning rate).

The one-term difference in numbers. Suppose the agent moves from s2 to s3 (reward −1) and, at s3, knows Q(s3, right) = 4.25 but happens to explore and pick "left", where Q(s3, left) = 0.8. With γ = 0.9: the SARSA target is −1 + 0.9 × 0.8 = −0.28 (it credits what really happened next), while the Q-learning target is −1 + 0.9 × 4.25 = 2.83 (it credits the best that could have happened).

By hand: Q-learning on the same three moves

All Q-values start at 0, α = 0.5, γ = 0.9, terminal states have value 0.

1. (s3, right) gives −1 and lands in s2: Q(s3, right) ← 0 + 0.5 × [−1 + 0.9 × max Q(s2, ·) − 0] = 0.5 × (−1 + 0) = −0.5.

2. (s2, right) gives −1 and lands in s3: the best known value at s3 is max(Q(s3, left) = 0, Q(s3, right) = −0.5) = 0, so Q(s2, right) ← 0.5 × (−1 + 0.9 × 0 − 0) = −0.5.

3. (s3, right) gives +9 and ends: Q(s3, right) ← −0.5 + 0.5 × [9 + 0 − (−0.5)] = −0.5 + 4.75 = 4.25.

Do it on a 3-state robot and you would call it a toy; do it on a table with thousands of entries, repeated for millions of steps, and you have an agent that learns to play games.

6. The cliff: on-policy vs off-policy in practice

The classic experiment: a 4 × 12 grid. Start at the bottom left, goal at the bottom right, and between them a cliff: stepping on it costs −100 and sends the agent back to the start. Every other step costs −1. The shortest path runs right along the edge of the cliff. With ε-greedy exploration (ε = 0.1), an agent walking along the edge will occasionally take a random step off it.

The two algorithms learn different things: Q-learning learns the best path (the edge route, 13 steps: what you would do if you could stop exploring); SARSA learns the best behaviour given that it explores: it keeps a safe distance from the edge, because SARSA's values include the cost of its own random slips. So while learning, SARSA falls less and earns more reward; if you switch exploration off afterwards, Q-learning's path is better. Neither is "right": it depends on whether the reward during learning matters (a robot that can break) or only the final policy (a simulation).

I also ran this with the real Gymnasium CliffWalking environment (500 episodes, ε = 0.1, α = 0.5, 10 different random seeds): Q-learning's average online reward over episodes 100 to 500 was −49.8 and its greedy path was the 13-step edge route in all 10 runs. SARSA's was −27.2, with a greedy path of 17 steps in 7 of 10 runs (19 in one). One thing I did not expect: in 2 of the 10 SARSA runs the final greedy path did not reach the goal within 100 steps (it got stuck going back and forth), a reminder that a table learned with exploration in it can behave oddly when you suddenly turn exploration off.

Press "Train +2000 episodes" a few times (the defaults are a small learning rate, α = 0.05, and heavy exploration, ε = 0.5: Q-learning is off-policy, so it can explore a lot and still learn the values of the best policy). After 10,000 episodes the largest gap to the planner's values was between 0.03 and 0.12 in my runs, and the greedy arrows match the planner's. It needed thousands of episodes of real (here, simulated) experience where value iteration needed 28 quick sweeps: this is the price of not having a model. In exchange, model-free methods need no model at all, work when the model is too complicated to write down, and are the basis of most modern deep RL.

8. Model-free RL in Python

Everything above fits in a few lines with gymnasium (pip install gymnasium). This is Q-learning and SARSA on the slippery FrozenLake from last lesson, where the planner (with the model) achieved 74.8% success. All results are from an actual run (gymnasium 1.3.0, one run per setting, so expect some variation):

import numpy as np, gymnasium as gym

env = gym.make("FrozenLake-v1", is_slippery=True)
rng = np.random.RandomState(0)
Q = np.zeros((16, 4))                                  # a table: 16 states x 4 actions
alpha, gamma, episodes = 0.1, 0.99, 30000

for ep in range(episodes):
    eps = max(0.05, 1.0 - ep / (0.6 * episodes))       # explore a lot at first, then less
    s, _ = env.reset(); done = False
    a = rng.randint(4) if rng.rand() < eps else int(Q[s].argmax())
    while not done:
        s2, r, terminated, truncated, _ = env.step(a); done = terminated or truncated
        a2 = rng.randint(4) if rng.rand() < eps else int(Q[s2].argmax())
        target = r + (0 if terminated else gamma * Q[s2].max())     # Q-learning: best next action
        # target = r + (0 if terminated else gamma * Q[s2, a2])     # SARSA: the action actually chosen next
        Q[s, a] += alpha * (target - Q[s, a])
        s, a = s2, a2

# evaluate the greedy policy (always take the best action) in the real environment:
#   Q-learning, 30,000 episodes: 74.1% success   SARSA, 30,000 episodes: 74.0%
#   Q-learning after only 10,000 episodes: 73.6% after 2,000 episodes: 73.7%
# for comparison: random actions 1.3%, the planner with the full model 74.8% (100-step limit)

The model-free agent matches the planner's success rate, from experience alone: about 74%. (Its estimates of the exact values keep wobbling with a constant α, but the greedy policy is what counts here.) For the cliff, replace the environment name by "CliffWalking-v1" (with 48 states) and use ε = 0.1, α = 0.5, γ = 1 to reproduce the numbers above.

Key takeaways

  • Model-free RL learns values or policies straight from experience, with no model of the transitions or rewards.
  • ε-greedy balances exploring and exploiting. On the 10-armed testbed, ε = 0.1 earned 1.31 per pull versus 1.04 for pure greed.
  • Monte Carlo: average the full returns of complete episodes (unbiased, noisy, waits for the end). TD: V(s) ← V(s) + α [r + γ V(s′) − V(s)], update every step, bootstrapping (low variance, some bias). One TD step on the corridor took V(s3) from −0.5 to 4.25.
  • SARSA (on-policy): target r + γ Q(s′, a′) with the action actually taken. Q-learning (off-policy): target r + γ max Q(s′, ·). On the cliff, Q-learning finds the optimal edge path but earns less while learning (−49.8 vs −27.2); SARSA learns a safer path.
  • Q-learning on slippery FrozenLake reached about 74% success without a model, the same as the planner with the model, but needed tens of thousands of steps.
  • Tables do not scale; neural networks replace them in deep RL.
